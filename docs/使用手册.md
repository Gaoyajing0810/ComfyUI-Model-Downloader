## 快速上手

### 五句话版

1. 启动 `comfy-ui-model-downloader serve`，浏览器会自动打开
2. 把工作流 `.json` 拖进「导入工作流」页面
3. 在「下载计划」确认要下载的条目
4. 点「开始下载」，等进度走完
5. 回到 ComfyUI，刷新模型列表，工作流就能跑

### 五分钟版

```bash
# 1. 安装（从 GitHub Release 下载源码压缩包，解压后进入目录）
cd comfy-ui-model-downloader
pip install -e .

# 2. 先试试 CLI（不联网、不下载，最安全的验证）
comfy-ui-model-downloader scan workflow.json --comfy-root ~/ComfyUI

# 3. 看看模型社区有没有这些模型（联网，只看不下载）
comfy-ui-model-downloader plan workflow.json --comfy-root ~/ComfyUI

# 4. 确认无误，执行下载
comfy-ui-model-downloader fetch workflow.json --comfy-root ~/ComfyUI

# 5. 或者直接起 GUI
comfy-ui-model-downloader serve
# 浏览器打开 http://127.0.0.1:8188
```

## 图形界面

### 1. 准备工作

首次启动会要求选择 ComfyUI 根目录。

**ComfyUI 根目录长什么样？**

```
~/ComfyUI/
├── main.py          ← 这个文件应该在
├── comfy/           ← 这个文件夹应该在
├── models/          ← 这个文件夹必须在
│   ├── checkpoints/
│   ├── loras/
│   ├── unet/
│   └── ...
├── custom_nodes/
└── ...
```

工具会判断所选目录像不像 ComfyUI：

- 看到 `main.py` + `comfy/` + `models/`：完全像
- 看到 `comfy/` 但没 `main.py`：像，但可能不是标准安装
- 只有 `models/`：能用，但请确认这是你要的目录

**如果选错了怎么办？**

- 顶部「设置目录」随时改
- 配置文件在 `~/Library/Application Support/comfy-ui-model-downloader/config.toml`，手改也行

### 2. 导入工作流

把 `.json` 文件**拖到页面中央的虚线框**里，或者点击「选择文件」按钮。

工具支持的格式：

| 格式 | 说明 |
|---|---|
| API 格式（推荐） | ComfyUI「Save (API Format)」导出的格式 |
| UI 格式 | ComfyUI 默认导出的格式（含 `widgets_values`） |

**导入后页面会展示什么？**

每个工作流节点用到的模型，逐行列出：

```
状态    文件                                  目标子目录   本地状态
─────────────────────────────────────────────────────────────────────
已完成  dreamshaperXL_v21TurboDPMSDE.safetensors   checkpoints/ 已存在
待下载  qwen_image_edit_2511_bf16.safetensors      unet/       缺失
其他目录 lora_detail.safetensors                    loras/      其他目录
```

**本地状态共有四种：**

| 状态 | 含义 | 下一步 |
|---|---|---|
| 已存在 | 文件在正确目录且完整 | 跳过，无需处理 |
| 其他目录 | 同名文件在别的类别目录（如 lora 放进了 checkpoints） | 工具会提示具体位置，需手动判断 |
| 缺失 | 本地完全没有 | 下载计划页面会找来源 |
| 损坏 | 文件存在但大小或哈希不匹配 | 重新下载 |

### 3. 下载计划

从「导入工作流」下一步会自动跳到「下载计划」。

这一页做三件事：

**① 看匹配结果**

每个缺失模型会显示命中的模型仓库、置信度（`exact` / `basename` / `high` / `low`）、文件大小。

- **exact**：仓库 + 文件路径都匹配上，准确度最高
- **basename**：只有文件名相同，路径可能不一样
- 置信度低的条目旁边会有候选列表，手动选一个

**② 改来源（可选）**

点击某行的「魔搭来源」列，可以：

- 从候选列表里换一个仓库
- 粘贴一个自定义下载 URL（支持任意 HTTP/HTTPS 来源，包括 HuggingFace、GitHub Release、网盘直链）

**③ 选条目**

- 「全选」一键勾选全部
- 「清空」取消全部勾选
- 「反选」翻转勾选状态

底部实时显示「N 项待下载 · 合计 X GB」。**没勾的不会下载**。

确认无误后点右下角「开始下载」。

### 4. 下载

下载页有四块信息：

```
┌─ 顶部进度条 ──────────────────────────────┐
│ 总体进度  62%                              │
│ ███████████░░░░░░░░░░░░ 11.4 GB / 18.3 GB  │
│                              [取消] [返回]│
└────────────────────────────────────────────┘

┌─ 文件列表 ─────────────────────────────────┐
│ 状态  文件          进度     已下载/总量    │
│ 下载  qwen_image... 62% ████ 11.4/18.3 GB │
│ 完成  unet_helper   100%    1.2/1.2 GB    │
│ 失败  vae.safeten   -      错误：磁盘满  │
└────────────────────────────────────────────┘

┌─ 服务端日志 ──────────────────────────────┐
│ [10:23:14] 下载 qwen_image_edit ...        │
│ [10:23:15] HEAD https://... 200 OK        │
│ [10:24:02] 进度 11%  2.1 MB/s             │
└────────────────────────────────────────────┘
```

**底部「已完成」横幅**会列出：

- 安装位置（可一键复制到剪贴板）
- 总耗时、总流量、成功 / 失败数

**关于「取消」按钮**：

点取消后，**已经在传输中的文件**会收到中断信号尽快停；**还没开始的**直接跳过；**已经完成的**不会被删。下次重新运行会接着未完成的来（断点续传）。

### 5. 校验

「校验」页独立于下载流程，专门用来体检已有模型。

- **扫描范围**：默认全部 25 个模型类别，可在下拉框里筛选（如只查 `checkpoints`）
- **校验项**：文件大小 > 0、可读、头部 magic number、哈希（若开启 `deep_verify`）
- **问题文件**：红色列出，附错误描述
- **退出码**：命令行模式下有问题返回 `1`，全过返回 `0`，可塞进 CI

适合在做大量下载前、迁移模型盘后、或者怀疑文件损坏时跑一遍。

### 6. 历史

「历史」页记录所有过往任务：哪个工作流、何时开始、状态如何、传了多少流量。

用于：

- 复盘上一次漏下了哪些
- 查看失败条目的错误原因
- 统计总下载量

## 命令行

所有命令都支持 `--json` 输出，便于脚本化。

### `scan` — 只看不下载

```bash
comfy-ui-model-downloader scan workflow.json --comfy-root ~/ComfyUI
```

不联网，最快。在 CI / 检查脚本里用它判断「当前缺什么」。

### `plan` — 看会下什么

```bash
comfy-ui-model-downloader plan workflow.json --comfy-root ~/ComfyUI
```

联网匹配来源，但不下载任何东西。适合：

- 下载前看一眼来源是否靠谱
- 把 `plan --json` 输出喂给其他工具生成报告
- 加 `--offline` 跳过来源匹配，只看本地

### `fetch` — 真下

```bash
comfy-ui-model-downloader fetch workflow.json --concurrency 5
comfy-ui-model-downloader fetch workflow.json --dry-run      # 只打印要下哪些
```

下载顺序：先校验磁盘空间（不足直接报错），再并发启动。

退出码：

- `0`：全部完成
- `1`：有失败
- `130`：用户按 Ctrl+C 取消

### `verify` — 体检

```bash
comfy-ui-model-downloader verify --comfy-root ~/ComfyUI
comfy-ui-model-downloader verify --category checkpoints --category loras
```

不加 `--category` 时扫描全部类别。

### `serve` — 启动 GUI

```bash
comfy-ui-model-downloader serve --port 8188
```

首次启动会弹目录选择框（macOS），之后会记忆配置。

## 路径与目录

### 三个关键路径

| 名字 | 是什么 | 例子 |
|---|---|---|
| **ComfyUI 根目录** | ComfyUI 安装目录（含 `main.py` 和 `models/`） | `~/ComfyUI` |
| **模型目录** | 模型实际存放处 | `<根>/models` 或自定义 |
| **下载到的子目录** | 由模型类别自动决定 | `models/checkpoints/`、`models/unet/` |

### 25 个模型类别与对应目录

工具自动按引用类型把模型放进正确的子目录，不需要你手动选：

| 类别 | 主目录 | 别名目录 | 扩展名 |
|---|---|---|---|
| `checkpoints` | `checkpoints/` | — | `.safetensors` `.ckpt` `.gguf` |
| `loras` | `loras/` | — | 同上 |
| `vae` | `vae/` | — | + `.gguf` |
| `text_encoders` | `text_encoders/` | `clip/` | + `.gguf` |
| `diffusion_models` | `unet/` | `diffusion_models/` | + `.gguf` |
| `clip_vision` | `clip_vision/` | — | 同上 |
| `style_models` | `style_models/` | — | 同上 |
| `embeddings` | `embeddings/` | — | `.safetensors` `.pt` `.txt` |
| `controlnet` | `controlnet/` | `t2i_adapter/` | 同上 |
| `gligen` | `gligen/` | — | 同上 |
| `upscale_models` | `upscale_models/` | — | 同上 |
| `latent_upscale_models` | `latent_upscale_models/` | — | 同上 |
| `photomaker` | `photomaker/` | — | 同上 |
| `hypernetworks` | `hypernetworks/` | — | 同上 |
| `audio_encoders` | `audio_encoders/` | — | 同上 |
| `background_removal` | `background_removal/` | — | 同上 |
| `frame_interpolation` | `frame_interpolation/` | — | 同上 |
| `geometry_estimation` | `geometry_estimation/` | — | 同上 |
| `optical_flow` | `optical_flow/` | — | 同上 |
| `detection` | `detection/` | — | 同上 |
| `classifiers` | `classifiers/` | — | 同上 |
| `model_patches` | `model_patches/` | — | 同上 |
| `configs` | `configs/` | — | `.yaml` `.yml` |
| `diffusers` | `diffusers/` | — | 目录型 |
| `ipadapter` | `ipadapter/` | — | 同上 |
| `animatediff` | `animatediff/` | — | 同上 |

> 当某个类别在主目录找不到，会自动到对应别名目录查重（`text_encoders` 还会看 `clip/`、`controlnet` 还会看 `t2i_adapter/`）。

### 自定义目录

如果你把模型放在非标准位置（比如所有东西都堆在 `models/` 根目录），编辑配置：

```toml
# 关闭跨目录按 basename 匹配，让同名文件能被识别为同一份
allow_basename_match = false
```

或者直接用环境变量临时改：

```bash
COMFY_MODELS_DIR=/mnt/big-disk/models comfy-ui-model-downloader scan workflow.json
```

## 常见问题

### 启动相关

<details>
<summary><b>「未指定 ComfyUI 根目录」</b></summary>

任选一种：

```bash
# CLI：用参数
comfy-ui-model-downloader scan workflow.json --comfy-root ~/ComfyUI

# CLI：用环境变量
export COMFY_ROOT=~/ComfyUI
comfy-ui-model-downloader scan workflow.json

# GUI：点顶部「设置目录」
```

</details>

<details>
<summary><b>macOS 双击 .app 没反应</b></summary>

打开 Terminal，运行：

```bash
dist/comfy-ui-model-downloader.app/Contents/MacOS/comfy-model-downloader
```

看具体报错。常见原因：

- 没签名：首次打开需要在「系统设置 → 隐私与安全性」点「仍要打开」
- 没选目录：会弹原生选择框；如果环境是无图形界面会静默退出，加 `COMFY_FETCH_HEADLESS=1` 关掉弹窗

</details>

<details>
<summary><b>端口被占用</b></summary>

```bash
comfy-ui-model-downloader serve --port 9000
```

或者关掉占用 8188 的进程。

</details>

### 下载相关

<details>
<summary><b>下载到一半显示「网络错误」自动重试</b></summary>

这是默认行为：失败会自动重试 3 次（可在配置里改 `retries`）。如果一直失败：

1. 检查网络（`curl https://www.modelscope.cn`）
2. 弱网环境把并发调低：`--concurrency 1`
3. 配置魔搭 Token 提高配额

</details>

<details>
<summary><b>「磁盘空间不足」</b></summary>

下载前工具会检查目标盘剩余空间。需要 = 所有待下载文件大小之和。

清出足够空间或换到另一块盘：

```toml
# ~/.config/comfy-ui-model-downloader/config.toml
models_dir = "/mnt/external/models"
```

</details>

<details>
<summary><b>某个模型「未找到可信来源」</b></summary>

模型社区没有收录该文件。三种处理：

1. **手动指定 URL**：在下载计划页点该行的「来源」列，粘贴任意 HTTP/HTTPS 链接（HuggingFace、GitHub Release、个人网盘直链都行）
2. **手动下载**：从其他渠道下好后放进 ComfyUI 对应子目录，工具下次扫描会识别为「已存在」
3. **跳过**：取消勾选，不下这条

</details>

<details>
<summary><b>下载成功但 ComfyUI 找不到</b></summary>

最常见原因：放错目录。

工具按节点类型决定子目录，但 ComfyUI 自己也有内置规则。**核对一下**：

| 节点 | 工具放到 | ComfyUI 找 |
|---|---|---|
| `UNETLoader` | `models/unet/` | `unet` 或 `diffusion_models` |
| `DualCLIPLoader` | `models/text_encoders/` | `text_encoders` 或 `clip` |
| `VAELoader` | `models/vae/` | `vae` |

如果 ComfyUI 找不到，确认：

1. 在 ComfyUI 界面右上角点「Refresh」刷新模型列表
2. 看 ComfyUI 控制台有没有「[ERROR] No file named ... found」类日志
3. 用本工具的 `verify` 命令确认文件实际落在哪个目录

</details>

<details>
<summary><b>校验一直卡住 / 很慢</b></summary>

校验在算 SHA256，大文件（如 30GB SDXL）首次计算会慢几分钟。两种加速：

```bash
# 关闭深度校验（只检文件大小与可读性）
# 配合配置文件 deep_verify = false

# 或者只查关心的类别
comfy-ui-model-downloader verify --category checkpoints
```

</details>

### 工作流相关

<details>
<summary><b>导入工作流后列表是空的</b></summary>

可能原因：

- 工作流没有引用任何模型（纯图处理？）
- 工作流用的是自定义节点里的模型，节点名工具不认识
- 工作流文件格式不对（确认是 ComfyUI 导出的 JSON，不是别的工具的）

把工作流文件用文本编辑器打开看一眼，应该能看到 `"nodes": [...]` 里有 `class_type` 字段。

</details>

<details>
<summary><b>某些模型被归到了错误的目录</b></summary>

工具按规则表归类，少数自定义节点可能误判。临时解决：

下载完成后手动移动文件，并刷新 ComfyUI 模型列表。

永久修复：提 issue 并附工作流文件 + 节点名 + 你期望的目录，规则表会更新。

</details>

<details>
<summary><b>模型文件被识别为「损坏」但下载是新的</b></summary>

可能磁盘有问题。用磁盘工具做个 surface scan，或者换一块盘试试。

</details>

## 进阶用法

### CI / 脚本集成

```bash
# 在 CI 里先检查「是否所有模型就位」，全过才进下一步
if ! comfy-ui-model-downloader verify --comfy-root /opt/comfy --json | jq -e '.bad == 0' > /dev/null; then
  echo "模型目录有问题，部署中止"
  exit 1
fi
```

```bash
# 部署前先把缺失的自动补齐
comfy-ui-model-downloader fetch workflow.json --comfy-root /opt/comfy --json > fetch-result.json
test "$(jq -r .state fetch-result.json)" = "done"
```

### 自定义来源（私有仓库 / 直链）

在下载计划页点「来源」列，可以粘贴任意 HTTP/HTTPS URL。支持：

- HuggingFace：`https://huggingface.co/xxx/yyy/resolve/main/model.safetensors`
- 魔搭：`https://www.modelscope.cn/xxx/yyy/resolve/master/model.safetensors`
- GitHub Release：`https://github.com/xxx/yyy/releases/download/v1/model.safetensors`
- 网盘直链：`https://your-pan.com/d/xxx/model.safetensors`（需服务端允许直接下载）

### 提速 / 调优

```toml
# ~/.config/comfy-ui-model-downloader/config.toml

# 弱网环境：低并发、重试多
concurrency = 1
retries = 5
timeout = 60.0

# 千兆网络：高并发、关掉深度校验
concurrency = 8
deep_verify = false
```

### 与 ComfyUI 配合

下载完成后**不需要重启 ComfyUI**。在 ComfyUI 界面右上角找到「Refresh / 刷新」按钮，点一下就能看到新模型。
